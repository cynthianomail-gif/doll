# Unity 移植

最後更新：2026-10-19

## 為什麼移到 Unity

網頁原型（`prototype/index.html`）已經驗證了玩法：設計 → 排版 → 裁布 → 車縫 → 塞棉花 → 裝飾 → 交件，還有衣服、硬材質、盲盒與分享代碼。接下來要做正式版本（美術、音樂、更大的內容量、可能上 Steam），改用 Unity 比較好維護與擴充。

網頁原型會保留：一是當作設計的參考答案，二是繼續放在 itch.io 給人試玩、收集回饋。

## 專案設定

| 項目 | 設定 |
|---|---|
| 位置 | `unity/`（和網頁原型在同一個 Git 儲存庫） |
| Unity 版本 | 6000.3.26f1 |
| 範本 | 2D（URP，`com.unity.template.2d-cross-platform`） |
| 輸入 | Input System（新版） |
| AI 協作 | MCP for Unity（`com.coplaydev.unity-mcp`，Git 套件） |

打開方式：用 Unity Hub 開啟 `D:\Doll\unity`，打開場景 `Assets/_Doll/Scenes/Design.unity`，按 Play。

## 程式結構

```
Assets/_Doll/
  Scripts/
    Core/        資料與邏輯（不依賴畫面）
      ShapeMath.cs   極座標外形、凸起、多邊形工具
      DollData.cs    所有內容資料：身體、頭型、髮型、部件、布料、顏色、滑桿
      DollState.cs   一隻娃娃的設計資料，以及由它算出外形、部件位置、頭髮、點選
    Rendering/
      FabricTextures.cs  用程式產生布料／搪膠／木頭的重複紋理
      DollRenderer.cs    把娃娃畫成程序網格（紋理＋頂點色陰影＋光澤）與外框線
    UI/
      DesignScreen.cs    設計畫面（暫用 IMGUI）
  Editor/
    DollSetup.cs     選單「Doll/建立設計場景」
    DollPreview.cs   選單「Doll/輸出範例娃娃截圖」（不用進 Play 就能檢查畫面）
  Scenes/Design.unity
```

### 座標約定

邏輯沿用網頁版的「畫布像素」座標：800×560、y 往下為正、娃娃基準半徑 R = 108。只有在畫的時候才轉成 Unity 世界座標（1 單位 = 100 像素，畫布中心在原點，y 翻轉）。這樣網頁版的所有數值和公式可以直接照搬，兩邊的行為一致。

## 進度

### M1：娃娃資料與渲染、設計畫面 ✅

- 網頁版的設計資料全部移植：6 種身體、4 種頭型、6 種髮型、耳朵／手／腳／肚子共 15 種部件、4 種布料＋搪膠＋木頭、16 種顏色與木材、16 條比例滑桿。
- 外形演算法一一對應：超橢圓＋凸起、人形頭身由滑桿自動排位、部件沿主體邊緣滑動、頭髮的瀏海／後髮／馬尾、身形與頭圍判定。
- 渲染：程序網格＋布料紋理、頂點色陰影、主體光澤、外框線；選取中的部位用橘色外框標示。
- 設計畫面：材質、娃娃類型、部位分頁、造型、比例滑桿、布料與顏色、「跟身體一樣」、部件拖曳（含對稱、大小、角度、重設）、滾輪縮放。

已驗證：
- 批次模式編譯無錯誤，四種範例（兔子布偶、人形雙馬尾、搪膠幽靈、木頭人形）輸出的截圖和網頁版外觀一致。
- 在編輯器 Play 模式中可以設定娃娃並正確繪製、標示選取部位。

尚未驗證：
- **設計畫面的介面（IMGUI）和滑鼠拖曳還沒有人實際操作過**：自動化截圖時 Unity 視窗不在前景，拍不到介面。請打開編輯器按 Play 試一下。

### M2：遊戲流程骨架 ✅

- 主場景 `Assets/_Doll/Scenes/Main.unity`（選單「Doll/建立主場景（完整流程）」可以重建），已設為建置的第一個場景。
- 狀態機 `Session`：依材質走不同步驟——布偶「接單 → 設計 → 排版 → 裁布 → 車縫 → 塞棉花 → 裝飾 → 交件」、搪膠「… → 灌模 → 修毛邊 → 上色 → …」、木頭「… → 鋸外形 → 雕刻 → 砂磨 → 上色 → …」。設計沒選身體布料不能往下走。
- 訂單資料：網頁版的 15 位娃娃客人全部移植（需求標籤、柔軟度、預算、交件台詞、指定材質／類型）。第一位固定是林太太（新手教學），之後隨機輪流，可以換一位客人。
- 帳本：布料／材料費、配件費、合計對預算；錢包、聲望、完成件數。布料費在排版小遊戲移植前，先依布片面積估算（假設排得普通）。
- 交件評分：和網頁版同一套隱藏標籤比對（造型、部件、比例、布料、顏色、配件），加上柔軟度、手工品質、預算，給星等、酬勞、客人評語，交件後才揭曉客人在意的項目。
- 還沒移植的製作小遊戲先顯示「暫代」面板：用滑桿設定精準度、棉花量、外殼厚度等結果，讓流程能走完；之後每移植一個小遊戲就由它寫入這些數值。

已驗證：
- 選單「Doll/流程自我測試」14 項全部通過（新手第一單、設計擋關、三種材質的步驟、帳本與錢包、指定材質判定、配件計入花費與標籤）。
- Play 模式中從接單一路走到交件：畫面切換、設計畫面開關、星等與金錢都正確，沒有錯誤。

尚未驗證：
- **流程畫面的介面（IMGUI）同樣還沒有人實際點過**。請打開 Main 場景按 Play 走一輪。

## 已知事項

- 設計畫面暫用 IMGUI，目的是先把邏輯移過來。正式介面會在美術階段改成 UI Toolkit；邏輯都在 `DollState`，換介面不用動它。
- 內容資料目前寫在 `DollData.cs` 裡；之後會改成 ScriptableObject，讓企劃不用改程式就能調整。
- 第一次打開專案時，Unity 會匯入大量資源，編輯器可能有一兩分鐘反應很慢，屬於正常現象。
- 編輯器啟動時主控台可能出現一則 `SearchDatabase` 的 `ArgumentOutOfRangeException`，那是 Unity 內建的搜尋索引，和遊戲程式無關。
